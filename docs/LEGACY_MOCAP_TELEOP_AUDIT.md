# 旧体感遥操作工程审计

审计对象是本机 `teleop_tupian/teleop` 中的旧 Qt + Axis Studio/Noitom +
JAKA 双臂遥操作工程，以及现场飞书操作手册。该目录包含大量厂商 SDK
和二进制库，只作为只读证据保留，不上传到本仓库。

本文不记录任何现场电脑或 SSH 密码。

## 1. 结论

旧工程有参考价值，但不能作为当前 ZLink2 → Armstrong ROS2 安全执行程序直接
运行。值得继承的是参数证据、设备信息、8 ms 时序、夹爪寄存器和数据记录思路；
不能继承的是自动上电/使能、双臂同时连接、硬编码路径、缺少执行端二次限位和
缺少断线看门狗的控制方式。

当前项目继续采用：

- Windows 只读主臂；
- Ubuntu ROS2 单右臂执行；
- 带起始偏移的绝对关节映射；
- 桥接层和执行层双重限位；
- 独立上电、机器人使能、伺服和映射四道门；
- deadman、STOP、命令/反馈看门狗；
- 每轴限速、限加速度与 125 Hz 执行周期。

### 文件夹组成

本地旧包约 0.766 GB、787 个文件，其中 `lib/` 约 772 MB，主要是 FFmpeg、
OpenCV、Orbbec、HDF5、JAKA 等预编译依赖；`include/` 约 10.2 MB，主要是第三方
头文件。项目级源码、配置和脚本合计不到 1 MB。包内没有视频、图片、PDF 或 Word
采集资料；代码虽然具备录制 MP4/HDF5/CSV 的功能，但实际采集数据未包含在包内。

## 2. 旧程序实际做了什么

`mainwindow.cpp` 构造函数会直接：

1. 登录右臂 `192.168.2.226:10020`；
2. 退出伺服、终止旧运动；
3. 给右臂上电并使能；
4. 对左臂 `192.168.2.225:10010` 重复相同操作。

它没有检查每个调用的返回值，也没有让操作者分别确认上电和使能。当前项目绝不
复制这种启动行为。

界面中的旧流程是：

- 按钮 1：先移动到硬编码右臂初始姿态，再等待动捕结果并移动到动捕初始姿态；
- 按钮 2：进入伺服模式，同时启动机械臂与相机记录线程；
- 按钮 3：设置全局退出标志并退出；
- 按钮 4：另外调用左右臂 `disable_robot()`。

因此旧手册里“按 1 后机械臂会动两次”与代码一致。按钮 3 本身没有可靠保证退出
伺服并下使能，这也是当前项目必须保留独立 STOP 和看门狗的原因。

## 3. 右臂候选关节限位

旧程序实际加载 `conf/robot_7dofs_0822_1.conf`。该文件设置：

```json
"URDF": "robot_7dofs.urdf",
"UsingJointLimits": true
```

对应 URDF 的右臂范围为：

| 关节 | 下限 rad | 上限 rad | 约合角度 |
| --- | ---: | ---: | ---: |
| J1 | -6.2832 | 6.2832 | -360°～360° |
| J2 | -1.8325 | 1.8325 | -105°～105° |
| J3 | -6.2832 | 6.2832 | -360°～360° |
| J4 | -2.5307 | 0.5235 | -145°～30° |
| J5 | -6.2832 | 6.2832 | -360°～360° |
| J6 | -1.8325 | 1.8325 | -105°～105° |
| J7 | -6.2832 | 6.2832 | -360°～360° |

该 URDF 共引用 90 个 STL 网格，包括右臂 `r1.STL`～`r7.STL`、左右臂底座和
灵巧手零件，但这些 STL/DAE/OBJ/STEP 文件并不在本地旧包中；Ubuntu 用户目录下
也没有找到 `r1.STL`～`r7.STL`。因此 URDF 能证明旧系统预期存在配套显示网格，
不能证明该文件夹包含 CAD 图纸。关节树、转轴、坐标和限位仍可脱离 STL 使用。

这些值也重复出现在多个 `retarget*.json` 的 `min/max` 中，而且相应条目设置了
`useAngleLimit: true`。但当前 `mainwindow.cpp` 没有加载这些 JSON；当前可执行
路径明确加载的是 `.conf + URDF`。

这些范围不能直接解锁当前执行器，原因是：

- J1/J3/J5/J7 的 ±360° 很宽，更像模型或重定向范围；
- URDF 把七轴 `velocity` 和 `effort` 都写成 0，不能作为速度/力参数；
- 旧主循环收到闭源重定向库输出后，直接调用 `edg_servo_j()` 和
  `edg_send()`，没有再次逐轴检查范围、NaN、速度或加速度；
- 还没有从 Armstrong/JAKA 控制器界面确认真实控制器软限位；
- 摇操任务还需要比控制器软限位更窄的任务限位。

所以该表只作为“候选控制器范围”保存。下一步仍需读取控制器/示教器的真实软
限位，再根据桌面、机械臂本体和任务区域设置更窄的右臂任务限位。

## 4. 旧初始姿态和映射

旧配置为右臂写过一组动捕重定向初始值：

```text
[0.0, 1.42, -1.67, 0.0, -1.51, 0.0, -1.51] rad
```

旧界面按钮 1 实际硬编码姿态是：

```text
[0.035, 1.427114, -1.670050, -0.027259,
 -1.513450, -0.068242, -1.513177] rad
```

它可以作为“旧系统曾经使用的姿态”参考，但不能自动当作当前安全 Home，也不能
在未检查周围环境时发给真机。

`retarget*.json` 中的 `sign/offset/rawJoint` 是人体骨骼到机器人关节的映射。
ZLink2 主臂的轴方向、零点和编码器单位完全不同，因此这些 sign/offset 不能复制
到 `teleop_bridge.yaml`。当前项目仍需逐关节计算：

```text
q_target = q0 + sign × scale_rad_per_pulse × (p - p0)
```

## 5. 8 ms、滤波与速度

旧程序的执行循环：

- 使用绝对模式 `edg_servo_j(..., ABS)`；
- 每帧调用 `edg_send()`；
- 通过绝对时钟睡眠保持 8 ms 周期，即 125 Hz；
- 进入伺服前调用 `servo_move_use_joint_LPF(0.5)`；
- 尝试把线程设置为 `SCHED_FIFO`、优先级 99。

这确认了当前项目采用 8 ms JAKA 执行周期的方向。`LPF(0.5)` 的精确定义和延迟
仍未在当前 SDK/真机上测量，不能直接启用。当前项目先使用可审计的中值、低通、
编码器死区以及执行端速度/加速度斜坡；真机标定后再决定是否叠加 JAKA LPF。

旧 JSON 中的速度值在不同版本间差异很大：有的高达 `31.4159 rad/s`，有的为
J1～J4 约 `5 rad/s`、J5～J7 约 `1 rad/s`。它们不适合作为首次摇操速度。
当前首次测试继续保持 `0.10 rad/s` 和 `0.20 rad/s²` 的保守上限。

## 6. CTAG2F120 夹爪证据

旧 `ZX_gripper` 驱动和现场曾运行的 ROS2 节点共同支持以下信息：

- Modbus RTU：115200、8N1、slave ID 1；
- 旧默认开位置：`0`；
- 旧默认关位置：`12000`；
- 旧界面默认速度：100%，默认力：40%；
- 临时目标位置寄存器：`0x0102/0x0103`；
- 速度/力：`0x0104/0x0105`；
- 加速/减速：`0x0106/0x0107`；
- 触发：`0x0108`；
- 力矩到达：`0x0601`；
- 位置到达：`0x0602`；
- Ready：`0x0604`；
- 位置反馈：`0x0609/0x060A`；
- 报警：`0x0612`。

这让 `0/12000` 从猜测升级为强候选值，但仍不能立刻把
`configuration_complete` 改为 true。需要用当前只读探针确认：

- 当前实物的反馈方向确实为 0 开、12000 关；
- 两个任务安全端点不造成机械挤压；
- 低速/低力夹到物体时 `torque_reached` 能可靠停止；
- 稳定 `/dev/serial/by-id/...` 对应的就是该夹爪；
- 首次运动使用远低于旧程序的速度和力。

## 7. 相机与数据记录

旧程序提供了可用的数据采集设计线索：

- Orbbec RGB + depth，配置为 1280×720、30 Hz；
- `record.yaml` 的根目录是 `/workspace/`；
- 旧相机序列号：
  - head camera：`CP8A9450002M`
  - right wrist camera：`CP8A9450001Z`
- RGB 保存为 H.264 MP4；
- depth 逐帧 PNG 编码后写入 HDF5；
- RGB/depth 使用同一帧编号和颜色帧系统时间戳；
- 机械臂 CSV 保存实际七轴和笛卡尔状态；
- 动捕 CSV 保存目标七轴、手指值和夹爪目标；
- 保存队列最多 5 帧，跟不上时丢弃数据，但没有可靠的丢帧统计；
- ZMQ 发布设置 `conflate=1`，只保留最新图像，避免网络积压导致控制延迟。

这些思路对 SmolVLA 数据集很有帮助，但旧格式仍缺少：

- 主臂、目标、从臂反馈、夹爪和相机的统一时钟说明；
- episode 成功/失败、任务文本和停止原因；
- 丢帧/丢周期计数；
- Git 提交、配置快照和机器人安全状态；
- 原始控制目标与经过限速后的实际发送目标区分。

当前项目继续使用 `tools/ros2_episode_recorder.py` 记录 ROS bag 和
`episode_metadata.json`；旧 `/workspace/` 只作为历史数据位置，不作为当前
代码中的硬编码目录。

## 8. 飞书现场手册中可继承的经验

可继承：

- 主控设备必须先佩戴/校准，再允许启动遥操作；
- 启动前逐个检查传感器、相机、夹爪和机器人状态；
- 实体急停必须在操作者可触及范围内；
- 先做目标预览，再允许真机；
- 采集完成后核对源数据和外置硬盘副本；
- 统计每次采集的有效时长；
- 明确串口设备可能重编号。

需要改进：

- 不使用 `chmod 777 /dev/ttyACM*`；改用稳定
  `/dev/serial/by-id/...`、`dialout` 组或最小权限 udev 规则；
- 不通过反复急停复位来解决卡顿；先关闭运动门、下使能并检查错误码和周期统计；
- 不用裸 `cp -r` 加 `du -sh` 作为唯一完整性证明；应使用
  `rsync --archive --checksum`、清单或哈希，验证成功后再人工决定是否删除源数据；
- 不把密码写进代码、README、脚本或 Git；
- 不依赖“关闭 GUI 就已经安全停止”的假设；
- 不通过程序自动寻找关节或夹爪物理极限。

## 10. 下一步

1. 从 Armstrong/JAKA 控制器或示教器读取右臂真实软限位。
2. 根据实际桌面和任务区域设置更窄的七轴任务限位。
3. 在 `dry_run` 下逐轴标定 ZLink2 的 sign 和 scale。
4. 用只读夹爪探针验证 0/12000、报警和力矩到达。
5. 确认真机 ROS2 相机话题或为 Orbbec 建立发布节点。
6. 低速单关节测试通过后，再启动完整 episode 记录。
